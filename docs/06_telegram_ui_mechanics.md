# Механики Telegram UI и UX («Живая Таверна»)

Данный документ описывает реализацию интерфейса и пользовательского опыта с учетом жестких технических ограничений Telegram Bot API (лимиты на Payload, Flood Control).

## 1. Паттерны управления состоянием (State Management)

Telegram-клиент выступает исключительно в роли View (тонкий клиент), а сервер бота инкапсулирует Controller и Model.

### 1.1. Обход лимита Payload (64 байта)
**Ограничение:** Размер `callback_data` для `InlineKeyboardButton` строго ограничен 64 байтами.
**Решение (Server-Side State):**
Все `callback_data` хранят только короткий идентификатор действия (`action_id`). Контекст сессии, состояние экрана инвентаря или аукциона лежит исключительно в in-memory БД (Redis) для скорости доступа O(1) по ключу `session:{chat_id}:{message_id}`.

### 1.2. Система очередей обновления View (Debouncing) и Кулдауны
**Ограничение:**
- Flood Control не позволяет делать более ~30 `editMessageText` в секунду на бота, и более 1 в секунду на конкретный чат (`429 Too Many Requests`).
- Клиент Telegram блокирует inline-кнопку («часики» загрузки) на время сетевого пинга до получения `answerCallbackQuery`. Полноценный высокочастотный спам по одной кнопке физически невозможен.

**Решение:**
- **Debounce-воркер:** Клиентские действия мгновенно обновляют In-Memory состояние в памяти. Фоновый асинхронный воркер делает ровно один `editMessageText` раз в 1 секунду.
- **Изоляция ошибок 400:** Перед сетевым вызовом хэшируется текущее состояние View. Если текст/кнопки не поменялись, запрос не отправляется (избегаем `400 Bad Request: message is not modified`).
- **Система кулдаунов (Dota/LoL style):** Вместо механики быстрого спама используется система перезарядки способностей. Время отката отображается прямо на кнопках (например, `⏳ 4с | 🔥 Огненный шар`).
- **Моментальный сброс блокировки (Fire-and-Forget):** Обработчик кнопки сразу отправляет `answerCallbackQuery` в фоновой задаче (`asyncio.create_task`), возвращая управление боту за 0-1 мс. Если способность на перезарядке, пользователю моментально отдается уведомление (`show_alert=True`) с оставшимся временем.

### 1.3. Разделенный интерфейс (Multi-message Layout)
Для создания ощущения "движка" игра не обновляет одно гигантское сообщение:
- Отправляются два сообщения. Верхнее закрепляется в чате (`pin_chat_message`) и содержит сетку кнопок или карту.
- Нижнее сообщение служит текстовым логом.
- Нажатия на кнопки верхнего сообщения вызывают `editMessageText` **только** для нижнего. Это экономит трафик и убирает визуальное "прыгание" интерфейса.

## 2. Форматирование и Rich Media

### 2.1. Скрытый лор (Blockquote Expandable)
Длинные литературные тексты от LLM (результаты экспедиций, отзывы) прячутся под тег HTML:
`<blockquote expandable>Текст лора...</blockquote>`
Текст автоматически сворачивается в плашку клиентом Telegram, экономя место на экране мобильных устройств.

### 2.2. Псевдографика (Матрица Эмодзи)
Генерация графики (например, барная стойка или склад) из массивов 5x5. Для оптимизации используются короткие коды эмодзи или кастомные стикерпаки Premium (`messageEntityCustomEmoji`).

### 2.3. Стилизация Inline-кнопок эмодзи-маркерами
**Ограничение:** Стандартное Telegram Bot API не поддерживает нативное изменение цвета (стили типа primary/danger) для `InlineKeyboardButton` (это возможно только в Web Apps).
**Решение:**
Для визуального разделения действий используются стандартизированные эмодзи-префиксы:
- 🗡 / 💥 — атакующие действия, нанесение урона.
- 💚 — лечащие/восстанавливающие действия.
- ⏳ — состояние перезарядки (блокировка действия).
- ⚙️ / 💼 — настройки, инвентарь и системные экраны.

## 3. Нативные аппаратные и социальные функции

### 3.1. Бросок кубиков (RNG на клиенте)
Используется метод `sendDice(emoji="🎰")`.
Telegram API сразу возвращает итоговое значение (для слотов `dice.value` от 1 до 64), а клиент проигрывает аппаратную 3D-анимацию. Бэкенд засыпает на время анимации (~2-3 сек) и затем обрабатывает результат. Исключает клиентский фрод.

### 3.2. Экранные эффекты (Haptic Feedback)
Передача параметра `message_effect_id` (например, "Огонь") при вызове `sendMessage`. Клиент реагирует вибрацией и полноэкранной анимацией (используется при выпадении легендарного рецепта).

### 3.3. Глобальный Inline-режим
Игрок вводит `@beer_empire_bot sell 100` в любом чужом чате. Бот генерирует `InlineQueryResultArticle`. Если кто-то жмет "Купить", бот получает Callback с `inline_message_id` и проводит транзакцию, параллельно обновляя карточку в чате на "Продано".
