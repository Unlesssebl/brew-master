# **База знаний ИИ-агента: Разработка нативных Telegram-игр (Bot API)**

Данный документ строго структурирован и оптимизирован для парсинга ИИ-агентами (LLM). Он содержит выжимку архитектурных паттернов, технические ограничения системы (Rate Limits, Payload) и методы их обхода для разработки нативных игр в интерфейсе Telegram.  
 

## **1\. Архитектура и управление состоянием (State Management)**

Нативные Telegram-игры реализуются на базе паттерна MVC, где Telegram-клиент выступает исключительно в роли View (тонкий клиент), а сервер бота инкапсулирует Controller и Model.

* **editMessageText:** Метод для мгновенного обновления текстового стейта (логи, инвентарь, характеристики).  
* **editMessageMedia:** Метод для изменения визуальной сцены. *Критический паттерн производительности:* предварительно загружайте медиа-ассеты в приватный технический канал, получайте  
  `file_id`(строка \~120 байт) и используйте исключительно этот идентификатор для рендеринга через CDN Telegram, избегая повторной загрузки по HTTP.  
* **editMessageReplyMarkup:** Легковесная операция обновления кнопок без рендеринга нового медиа.

 

## **2\. Форматирование: Экосистема Rich Messages (API 10.1+)**

Современный стандарт разработки требует отказа от хрупкого MarkdownV2 экранирования в пользу строгой объектной типизации компонентов.

* **sendRichMessage:** Отправка структурированного контента с использованием встроенных классов (  
  `RichBlockList`,  
  `RichBlockTable`,  
  `RichTextSpoiler`).  
* **sendRichMessageDraft:** Инновационная потоковая передача данных (streaming). Идеально подходит для трансляции ответов Game Master'а на базе LLM в реальном времени с сохранением разметки (таблиц и списков).  
* **messageEntityCustomEmoji:** Рендеринг 2D-карт (кастомных тайлов: трава, стены, мобы) прямо в текстовом логе с использованием матриц из кастомных эмодзи.

 

## **3\. Контроллеры ввода и обход лимита Payload (CRITICAL)**

**ЖЕСТКОЕ ОГРАНИЧЕНИЕ ПЛАТФОРМЫ:** Размер параметра

`callback_data`

для кнопок

`InlineKeyboardButton`

строго ограничен **64 байтами**. Ниже представлены стратегии архитектурного обхода.

| Паттерн обхода (64 байт) | Описание механики | Trade-offs (Плюсы и Минусы)   |
| :---- | :---- | :---- |
| Bitwise Encoding / Base64 | Упаковка множественных ID в бинарный формат с конвертацией в Base64. | Stateless подход. Ограниченная емкость, высокая сложность отладки. |
| Server-Side State (Redis) | Передача короткого UUID/хэша. Полный JSON состояния хранится в RAM. | Неограниченный payload. Требует брокера кэширования и жесткого контроля TTL. |
| Фреймворк-Абстракции | Использование встроенных фабрик (напр., `CallbackData` в aiogram). | Высокая скорость разработки. Потребляет память процесса. |

   
**Визуальная семантика:** API позволяет стилизовать кнопки с помощью полей

`style`

(значения: primary, danger, success) и добавлять векторные иконки через

`icon_custom_emoji_id`

.

 

## **4\. Математическая модель RNG (Server-Side)**

Метод **sendDice** предоставляет криптографически безопасный генератор случайных чисел, рассчитываемый исключительно на серверах Telegram. Это исключает клиентский фрод.

* Базовые кубики (🎲, 🎯, 🎳): Диапазон возвращаемых значений **1-6**.  
* Спортивные (🏀, ⚽): Диапазон **1-5**.  
* Слот-машина (🎰): Диапазон **1-64**. Кодируется в системе по основанию 4 (Base-4).

**Алгоритм декодирования состояния слот-машины (Python/Pseudocode):**

`# V - Результирующее значение от Telegram API (от 1 до 64)`  
`V_norm = V - 1`

`# Декодирование барабанов (0: Bar, 1: Grape, 2: Lemon, 3: Seven)`  
`reel_left (A)   = V_norm % 4`  
`reel_center (B) = (V_norm // 4) % 4`  
`reel_right (C)  = (V_norm // 16) % 4`

`# Вероятность джекпота (7-7-7, что соответствует V=64) составляет:`  
`# 1 / 64 или 1.5625%`

 

## **5\. Социальные механики и мультиплеер**

* **restrictChatMember:** Метод модерации, адаптированный для игрового процесса. Идеально для реализации статусных эффектов (оглушение, "смерть" в Мафии) путем отключения права  
  `can_send_messages`.  
* **createForumTopic:** Автоматическая генерация изолированных топиков для инстансных подземелий, гильдий или сессий.  
* **ForceReply:** Принудительный захват контекста пользователя для текстового ввода, устраняющий race conditions в групповых чатах.  
* **Inline Mode:** Виральный компонент. Позволяет вызывать базу данных бота в стороннем чате (например, для применения скилла или отправки приглашения).

 

## **6\. Монетизация и виртуальная экономика (Telegram Stars / XTR)**

Telegram Stars обеспечивает нативные микротранзакции, обходя комиссии внешних сторов.

| Метод / Событие | Бизнес-логика в GameDev   |
| :---- | :---- |
| **sendInvoice** | Инициация покупки. Важно: для цифровых товаров указывать `currency = XTR` и оставлять `provider_token = ""` . |
| **sendPaidMedia** | Реализация лутбоксов или премиального арта. Изображение или видео скрыто за криптографическим пейволлом до момента оплаты. |
| **sendGift** | Механика конвертации игровых достижений ("ачивок") в цифровые подарки, привязанные к публичному профилю пользователя в Telegram. |

 

## **7\. Управление нагрузкой (Highload & Scaling)**

**КРИТИЧЕСКИЕ ЛИМИТЫ (Rate Limits):** Запрещено отправлять более **30 сообщений в секунду** глобально, и более **1 сообщения в секунду** в конкретный чат. Нарушение вызывает ошибку

`429 Too Many Requests`

.

* **Telegram Local Bot API Server:** Развертывание локального инстанса необходимо для высоконагруженных игр. Это снимает сетевой пинг до серверов Telegram и увеличивает лимиты обработки файлов.  
* **Паттерны Debouncing и Throttling:** Разделение бизнес-логики и View. Все клики игрока пересчитывают стейт в RAM (Redis), а визуальное обновление (  
  `editMessageText`) запускается по таймеру очереди (напр., каждые 1.5 сек).  
* **Изоляция ошибок 400:** Качественный агент должен хэшировать текущее состояние View. Отправка идентичного текста/кнопки вызовет ошибку  
  `400 Bad Request: message is not modified`. Сравнивайте кэшированный хэш перед сетевым вызовом.
